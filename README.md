## 二、启动

```bash
cd /Users/panyp/WorkBuddy/评级报告外部自动生成
PORT=8770 /Users/panyp/.workbuddy/binaries/python/envs/rating-flow/bin/python app/server.py
# 浏览器打开 http://127.0.0.1:8770
```

依赖：`python-docx`、`pymupdf`（已在 `rating-flow` 环境）。财汇 MCP 端点与密钥从 `~/.workbuddy/mcp.json` 读取，也可用 `CAIHUI_MCP_URL` / `CAIHUI_MCP_KEY` 覆盖；模型走 `~/.workbuddy/models.json`，不需要另填 API Key。

**访问口令**：打开页面先要口令，没进来之前整页糊在毛玻璃后面（`backdrop-filter: blur(16px)` + 半透明白），点不动也提交不了。默认口令 `ce-shi`，登录后页头「锁定」可退出。

口令来源优先级：环境变量 `REPORT_PASSWORD` → `data/auth.json` 的 scrypt 哈希 → 默认 `ce-shi`。想改就设环境变量（临时、不落盘）：

```bash
REPORT_PASSWORD='你自己定的' PORT=8770 ... app/server.py
```

`POST /api/password {"old":"ce-shi","new":"新的"}` 会把新口令以 scrypt（n=2^14）写进 `data/auth.json`，并让所有旧会话失效；`data/` 在 `.gitignore` 里，不会进仓库。

登录成功发一个 `secrets.token_urlsafe(32)`，服务端只存它的 SHA-256（`data/sessions.json`，30 天有效、最多 20 个会话），前端放 localStorage，之后每个请求带 `Authorization: Bearer`。**用 Bearer 而不用 Cookie**：GitHub Pages 上的页面调 127.0.0.1 属跨站请求，第三方 Cookie 会被浏览器拦掉（`SameSite=None` 还要求 Secure，本机 http 不满足），自定义头只要 CORS 放行就能带。下载是浏览器直接跳转、带不了头，所以 `?t=<token>` 也接受。

## 三、工作台怎么用

页面只有一件事：把四步走完。左侧是主体输入、四步进度与资料清单，右侧是报告纸面，改完就导出。

1. **检索主体**：输入工商全称（简称也能命中）。公告接口不限关键词时按日期倒序返回，所以这里**一次宽查询取回最近 60 条**，在本地按标题分成**跟踪评级报告**与**募集说明书**（各留 12 条）；只有某一类一条都没出现时，才带关键词补查那一次。常态只消耗 1 点财汇额度，最坏 3 点。不走工商、股权、评级历史、存量债券、财务指标、主营构成那六七个接口——单次返回体大、串起来要等十几秒，也把下游提示词撑得很大。
2. **读取材料**：默认勾选各类最新一份。PDF 下载到 `data/`，按页打分生成摘录：跟踪评级报告约 3.2 万字符，募集说明书约 2.6 万字符，一次生成的材料总量控制在 6 万字符上下。**三大报表页先占预算**——合并资产负债表、利润表、现金流量表（含跨页的后半张）优先入选，再按内容价值分配剩余额度；否则财务页会被业务章节挤掉，模型看不到最新一期数字，正文就会写「未披露」。
3. **生成草稿**：约 30–60 秒。台账没有财务数据时，财务表由模型从材料原文的「主要财务数据」表整理（期次取最近三期），程序负责清洗、补千分位、校验自洽；段落与判断由模型写。生成后先过一遍语言清洗（见下文「报告的语气不属于分析员」），再跑七类校验：摘要层数据、数字溯源、期次写法、财务表自洽、「整列未披露但材料里有对应年度报表」、来源交代残留、程度词与过短板块。
4. **校对导出**：页面上逐段可改（摘要、基本情况、总述、各分部、资产、债务、专题），改完导出 docx，文件名带日期，落在 `output/`。

**历史记录**：每次生成自动落一份到 `data/history/`（正文、用的哪几份材料、模型与 token、导出后的 docx 名），页头「历史」打开列表，可一键把某次草稿恢复到编辑区接着改，或直接下当次导出的 Word。列表只读索引文件，点开才读全文，不会因为攒了几十份就变慢；超过 200 条自动淘汰最旧的。

**打包归档**：纸面右上「打包下载」展开一份勾选清单——本次报告（以及此前几版，默认只勾最新一份）、本次读取过的原底稿 PDF（标注页数、大小、来自财汇还是本地上传），外加可选的草稿数据 JSON（正文与表格的结构化数据，方便下次接着改）。勾完得到一个 zip，报告在根目录，底稿归在 `原底稿/` 下。没导出过 Word 也能打包，清单里会出现「按当前内容现场排版」，打包时现生成一份。

**也可以完全不用财汇**：左侧「上传 PDF」支持点选或拖入本机文件，上传后自动解析，直接进第 3 步。上传走裸字节 POST（`/api/upload`），前端用 XHR 显示上传百分比。

**版式只有一条规则**：块与块之间空一行，块内不空。所谓「块」是摘要的正面／关注、基本情况、总述段、业务构成表、每个板块、资产段、财务表、债务段、专题段；「块内」指加粗总起句与它后面的正文——这两者本来就在同一个 Word 段落里，中间不会也不该出现空行。页面上这个间距只有一个来源（CSS 变量 `--pgap`），不再是各处手调的 8/12/22/26px；正文工具条的「段落空行」可以把它一键切成 0，页面与导出的 Word 用同一个开关（`draft.layout.para_gap`）。

**左侧四步是手风琴**：同一时刻只展开一步，展开的那张就是「当前在哪一步」——不用另看进度条。折叠态压平成浅底、无阴影，展开态白底加一档边框与轻阴影浮起来；完成过的卡片用白底与深一档的标签色，跟「还没开始」的浅灰区分开。动画走 `grid-template-rows: 0fr → 1fr`，内容长短不一也不会跳；折角图标同时转 90°。

前进是自动的：检索完成 → 展开「读取材料」，材料读完 → 「生成草稿」，草稿生成 → 「导出报告」。随时点前面某一步的标题就能回去（当前那步随即折叠，后一步一起收回），每步底部还有「下一步 →」，该步完成后才可点。没走到的步骤是锁着的，点了不动。

**手机上能用**：≤640px 走一套单独的版式——顶栏变成一条可横滑的动作带（折行会吃掉 88–126px，等于少看半屏正文）、两栏合成一条滚动轴、悬浮面板一律改成底部抽屉、表格整表横滑且首列吸附、删除键与候选条常显（触屏没有 hover）、所有输入框 16px（低于这个值 iOS 聚焦时会放大整页且退不回去）。正文进入视野后右下角浮出「↑ 流程／正文 ↓」，生成完成会自动滚到正文。

**摘要从正文倒抽**：模型写完正文后回头逐段读，把「能独立成立、且对偿债有含义」的判断句圈成候选池（`positive_pool` / `concern_pool`，各 5–8 条），再从中挑 3–5 条定稿。页面上每条列表下面就是这批候选，点一条就加进去、加过的随即消失——不用为了多一条观点去重新描述一遍。

**报告的语气不属于分析员**：报告是评级机构对受评主体的判断，句子的主语只能是公司、股东、政府、行业或政策。所以正文不出现「材料」「材料原文」「公开资料」「本报告」，也不出现「披露」「未披露」「载明」「列示」「数据显示」「详见下表」这类转述来源的词，更不写「从外部条件看」「从内部条件看」这种把分析框架暴露给读者的提示语。提示词里已列为硬规则，`generator.polish_language()` 再兜一道：先擦掉「材料显示」「据材料」这类前缀（句子多半擦完就能用），擦不干净的按小句摘除，并把「授信方面，材料未披露。」这类只剩话题引子的碎句整句去掉。「原材料」「新材料」「材料成本」是业务用语，不会被误删。缺数据时的正解是**整拍跳过**，不是写「未披露」——财务表单元格除外，那里无值填「—」。

**进度不是装饰**：四步都是后台任务（`app/jobs.py`），前端按 `job_id` 轮询真实百分比——检索显示查到哪个关键词，读取材料显示每一份在「下载 12.4MB」还是「解析 74/107 页」，生成显示已用时。没开始的步骤整体灰掉，已完成的打勾。

**模型从哪来**：不另配 Key，直接读 WorkBuddy 自己的 `~/.workbuddy/models.json`（`url` + `apiKey` 都用它），调 OpenAI 兼容的 `/chat/completions`。所以 token 记在模型厂商的账单上，不占 WorkBuddy 额度；目前实际跑的是 `deepseek-v4-flash`（`api.deepseek.com`）。

这份配置里的条目并非都能从本进程直接调：OpenCode Go 那组要求 `x-opencode-session` 请求头（WorkBuddy 自己会补，我们不补），`GLM-5.3-Flash` 的 url 少了 `/chat/completions`，`sensenova` 的模型 id 对不上。全部列进下拉等于让人选一个必报错的，所以加了**模型体检**：服务启动时后台线程对每个模型发一个 `max_tokens=1` 的请求探活，结果落 `data/model_health.json`，下拉只列通得过的，其余折成一行「另有 N 个模型未通过验证」（鼠标悬停看各自原因）。`GET /api/models?refresh=1` 可强制重测。

对应接口：`POST /api/jobs/{search|fetch|generate}` 起任务并拿到 `job_id`，`GET /api/jobs/<id>` 读进度（含逐份材料的明细）；`POST /api/upload?name=文件名` 收 PDF；`/api/export` 仍是同步接口（排版只需秒级）；`GET /api/bundle?company=…&title=…` 列可打包的文件，`POST /api/bundle` 按勾选打 zip（同步返回下载地址）；`GET /api/history` 列历史、`GET /api/history/<id>` 取全文；`POST /api/analysis/list` 列分析附件清单、`POST /api/analysis/get` 取某一份全文（预览用）。

**分析附件（2 份 TXT）**：`<主体>-债券代码-<代表代码>.txt` 与 `<主体>-财务专项指标.txt`，形态与内部采集口径一致。

- 债券代码：数据来自财汇「企业发行的债券查询」（`get_company_issued_bonds`），全量含已到期与私募债，按品种分组、一行一只「简称｜代码｜规模｜期限｜起始日」；文件名带代表代码（最新一期交易所或银行间），私募债不入文件名但正文列全。**不从 PDF 猜**：评级报告只列存续那几只，代码与历史券不在里面。
- 财务专项指标：四项固定——① 市场地位（定位、持股、主体评级与机构日期、区域财力、资产与营收、业务结构）② 财报可靠性（审计机构 + 意见类型 + 结论）③ 受限资产占比（金额、占比、明细、原因）④ 应收账款账龄（一年以上占比，未披露就写【未披露】并给余额序列等替代信息）。
- 两条纪律：同一指标的金额与占比必须取自同一句同一期次（曾出现金额取 2025 年 6 月末、占比取 2025 年末，凑出一个「19.16 亿元占 11.78%」的错配）；半年、季度口径不与全年混比。合计口径与母公司口径同时存在时，取体量较大者（合并必不小于母公司），只用于挑表、不改数。

**盈利段与亏损归因**：点评在财务指标表之后、债务段之前新增「盈利段」，收入与利润分开写，亏损逐项归因（毛利 → 期间费用 → 资产与信用减值 → 投资收益／补助／处置／所得税），每项带金额、按影响排序，段末交代哪些偶发、哪些持续。总述段只给收入规模、构成与利润率方向，两段不重抄同一批数字。

**行业情况单列一节**：正文变「1、基本情况 → 2、行业情况 → 3、点评」。行业段只回答「量由什么决定、价由谁定」：供需格局（产量或需求增速、产能利用率、需求端构成）→ 价格与成本（价格走势与幅度、原材料与能源成本）→ 政策（真正影响这家公司的那一条）→ 对公司的传导。每个判断后面跟一个可核实的数；材料只给定性说法时，写到公司自己的量价上，不拿「行业景气度下行」这类套话充数。行业的量价政策在行业段写完，总述段只写公司自己的收入结构与盈利主线，同一组数据不在两处各写一遍。旧稿没有这一节时导出不留空节，点评编号自动回到「2、点评」，不会跳号。

**基本情况写明注册资本与实收资本**：注册资本是认缴额、实收资本是到账额，两者差着就说明还有没缴的部分，直接影响股东支持的成色；不一致时要说明差额原因，不能只写其中一个。

**没有变化的事不写**：控股股东及持股比例未发生变化、主体评级维持原级且展望未调整、审计机构未更换，都不写；董事长、总经理、董事的任免与内部部门调整这类与偿债能力无关的人事变动，也不写。判据是「把这件事写成一条公告，读者会不会改变『能不能按期还钱』的判断」，不会就整句删掉。反过来，控股股东变更为风险主体、控制权转移、评级下调或列入观察名单、审计意见类型变化必须写，并写出对信用水平的影响方向。程序对「股东未变／评级维持／审计机构未换／董监高变更」四类句式做兜底检查，列出原句让人确认删除。

对「不能瞎编」这一条，程序管两头：**财务指标表逐格溯源**——每一格都要能在材料里找到，或由同一列的其他数算出；找不到的置为「—」并列出是哪一行哪一期，绝不把子公司净利润、净资产收益率倒算值当合并数。**正文数字反解验算**——差额、合计、占比、增速按「句中的一个数 + 材料里的另一个数」反解（差额要 c = a − target，增速要 c = a ÷ (1 + target)），命中后再回代；只有句子里确实写着「增加／减少／合计」时才认差额与合计，避免「净利润 −8.39 亿元」被「13.49 − 5.11 = 8.39」验成通过。

**调用统计**：页头右上角一行「累计 N 次 · 财汇 M 点」，点开是明细——今日与累计的生成次数、财汇点数与 token，输入输出拆分、单次平均耗时、缓存命中率，检索／读取／生成／导出四类动作的累计次数，以及**最近调用逐条记录**（时间、动作、主体、这一下花了多少点或多少 token）。不按月切，看的是「这一次点了几下、累计用了多少」。数字全部来自模型返回的 `usage`（端点不回时才按字符估算并标「含估算」）。

财汇点数按调用二级工具的次数记（导航与元数据调用不计），每次检索结束时进度条上直接写「财汇 N 点」，和财汇后台的积分明细能对上。

统计落在 `data/usage.json`（已在 `.gitignore` 里），不是内存计数——服务是后台进程，被系统回收后内存清零，统计随重启归零就没用了。写入用临时文件替换，进程中途被杀也不会留下半个 JSON。`GET /api/stats` 返回同一份汇总。

## 四、分工原则（为什么不容易出错）

- **数字要有出处**：有台账时，业务构成表与财务指标表由程序按台账生成；没有台账（只检索公告或纯上传）时，财务表由模型从材料原文的「主要财务数据」表整理，程序负责补千分位、限三期、查自洽（资产 = 负债 + 权益），并在页面上标注「取自材料原文」。
- **判断归模型**：正文段落、正面／关注的提炼交给模型，但受模板槽位与写作纪律约束（摘要层不写数字、一段一事、不照抄评级机构结论、不按行业套路）。
- **校验兜底**：生成后自动检查七件事——
  - 摘要层是否混入金额／百分比（摘要应为纯定性）；
  - 正文数字能否在台账或材料原文里找到（找不到的会列出来，多为正文自行算的占比与增速，复核算式即可）。材料表格常以万元计、正文按亿元写，比对时两种口径都认；
  - 期次写法是否与台账/材料一致（不允许把「中报」写成 9 月末），且是否把材料里不同期次的数字拼到同一期次；
  - 财务表是否自洽（资产总额 = 负债 + 权益）；
  - 财务表某一期整列写「未披露」、但材料原文里有该年度报表时，单独提示——多半是摘录漏页或漏读，不是材料真的没披露；
  - 正文是否还残留交代资料来源的表述（程序已清洗一轮，漏网的多是句子结构太绕，提示里会截出原句）；
  - 是否含不可核实的程度词（极大、极强、恶劣、显著），以及有没有只剩一两句的过短板块段。
- **数字的三种口径不要混**：已实现营业收入 ≠ 合同金额或订单储备；净利润 ≠ EBITDA ≠ 经营现金流；年度 ≠ 单季 ≠ 累计；历史 ≠ 预测。这条写进了提示词，因为混用之后数字即使能在材料里找到，结论也是错的。

## 五、扩展：改规则，不改行业分支

- **加一类指标**：在 `01_模板/…_v1.1.json` 的 `indicator_layers.conditional` 里加一条，写清触发条件（字段可得、某科目占总资产的比例、某损益占利润总额的比例）与优先级。程序按触发条件自动决定这行出不出现，不需要给主体贴行业标签。`base` 是任何主体都有的必选行。
- **改口径**：自算比率在 `app/generator.py` 的 `_calc()`；触发条件解释器在同文件的 `_trigger_ok()`。
- **改版式**：`app/docx_writer.py` 落地模板「格式规范」——楷体_GB2312、五号、行距 1.15、首行缩进 2 字符、段前段后 0、标题与汇总句加粗；块与块之间用空段落分隔（参考件即如此，靠段前段后拉开会挤成一整片）；表格外框上下 1.5pt、内部横竖线 0.5pt、左右不封口，行高 0.4cm 起、单元格垂直居中、禁止跨页断行。
- **分部段不重复导语**：正文里「1）××业务方面，」由程序统一拼，模型只写其后正文。模型若自己写了同样的开头，`generator.clean_segment_body()` 会剥掉，避免出现「2）新材料业务方面，2）新材料业务方面，」。
- **分部段是一整段**：页面上每个板块都是一个整段可编辑区（编号、板块名、「业务方面，」和正文连排，像 Word 一样折行），不是「标题一行 + 正文一块」的两层结构——后者复制出来会变成三行。改板块名时后缀自动跟着变（名字本身以「业务/板块/产品/服务/行业」结尾就接「方面，」，否则接「业务方面，」），保存时按「编号 + 板块名 + 方面，+ 正文」反解。
- **同一件事只说一遍**：加粗句的判断不在正文里复述，专题段也不重抄债务段、资产段的数据。生成后程序做两轮去重——先比加粗句与正文（句子的字面重复整句删掉），再比同一段内的句子；跨段的重复只提示不删，因为业务段的风险点和专题段的证据常常是同一事实，该删哪一处得由人判断。判重时先把期次（2023年、2024年…）和「该板块收入分别为」「占营业收入的比重分别为」这类句式骨架抹掉，只比剩下的实质内容，否则每个板块段都会被判成互相重复。
- **粘连句直接删**：以「和/与/及 + 公司」开头的句子，是模型把上一段末尾与下一段开头粘在一起的产物（「…形成约束。和公司土地整理…」），语言清理时整句去掉。
- **导出前再清一遍**：`api_export` 会对前端传来的草稿跑 `generator.polish_draft()`——页面上手工改的文字同样要过语言清理与去重，因为 Word 才是最终形态。清理了几处会在导出提示里写明。
- **单独复用提示词**：页面上的「复制提示词」把系统提示＋用户提示整段复制出来，可贴到 WorkBuddy 用更强的模型精修同一份材料。

### 怎么发

```bash

python3 make_cloud.py           # 生成 _cloud/：程序 + 模板 + docs + versions + 启动脚本
```

然后用发布工具把 `_cloud/` 发上去（目录里 `start.sh` 含财汇与模型密钥，`_cloud/` 与 `_cloud_pw.txt` 都在 `.gitignore`）。

云端与本机共用同一份代码，靠环境变量补上「本机才有的配置」：

| 本机来源 | 云端替代 |
|---|---|
| `~/.workbuddy/models.json` | `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` |
| `~/.workbuddy/mcp.json` 的财汇条目 | `CAIHUI_MCP_URL` / `CAIHUI_MCP_KEY` |
| `data/auth.json` 或默认口令 | `REPORT_PASSWORD` |

**云端的三条实测教训**（都已修，记录下来免得再踩）：

1. **会话不能存文件**。原来 token 的 sha256 写 `data/sessions.json`，云端表现为「登录成功、紧接着带 token 就 401」——容器多副本/重启，写进去的读不回。改成 HMAC 自签 token：密钥由口令派生，服务端不存任何会话，改口令即全部失效。
2. **Authorization 头会被分享网关剥掉**。登录能过，后续请求全部「未登录」。改为同时下发 `Set-Cookie: nr_auth=…`（HttpOnly、SameSite=Lax），同源场景靠 Cookie，本机跨域仍用 Bearer，下载走 `?t=`。
3. **网关在缺 sharecode 时回 200 的 HTML 提示页**。前端只判断 `r.ok` 会把「链接不完整」页当成「后端在」，所以探活必须校验回的是 `{ok:true}` 的 JSON。

### 会话快照（进程重启不再丢材料）

`server.STATE` 是纯内存的，后端一重启材料清单、已生成的草稿、分析附件全部消失。材料是逐份解析 PDF 换来的（每份十几秒），丢一次就要重读一次。

`app/state_store.py` 把每个主体的 `facts / materials / base / draft` 落到 `data/state/<哈希>.json`：写盘在三处状态变更后触发（检索完、读材料完、生成完），启动时自动读回。边界是刻意的——只留最近 20 个主体、单份超过 12MB 不存、只恢复 14 天内的快照，因此不会被旧数据淹没。

**它解决的是「进程重启」，不是「容器重建」。** 云端容器整体重建时磁盘一起丢，那种情况需要对象存储或云数据库（本次云服务开通未完成，见版本记录）。本机运行不受影响，`data/state/` 已在 `.gitignore` 内。

数据不持久：容器重启后 `data/`（上传件、历史）与 `output/`（导出的 docx）清空。要长期留存就把成品当场下载，或走下面的本机方式。

### 为什么不维护两份

原来还有一份 GitHub Pages（`szsyqq.github.io/neiping-report-studio`），它是**纯静态**的：`/api/health` 返回 404，页面打开后要去连本机的 `127.0.0.1:8770`。也就是说它必须依赖这台 Mac 开着服务，手机和外网进不来；每改一次前端还得 `cp app/static/index.html site/index.html` 手工同步，漏一次两边就不一致。

所以停掉自动发布：`.github/workflows/pages.yml` 改成只 `workflow_dispatch`，`site/index.html` 换成一张迁移落地页（说明入口在哪、留三个链接），`site/docs/` 与 `site/versions/` 冻结在最后一次部署——模板与方法论不随功能变，历史快照本来就是历史。

**仓库照常推送**，`git log` 与 `versions/` 仍是完整的改动记录；变的只是「对外只有一个站点」。旧链接不会 404，会落到那张说明页。

要临时恢复自动发布，把 `pages.yml` 的 `on:` 加回 `push: branches: [main]` 即可。

## 七、版本历史

每次改动都留了一份**当时的页面**，不是截图，是那天的界面接现在的数据接口——点开能真的检索、生成、导出。

- `GET /versions` 时间线：所有版本、每版改了什么、一键打开
- `GET /v/<id>/` 某个版本的界面（也支持 `/versions/<id>/`）
- 工作台页头「版本」：同一个清单，带登录态直接打开旧版

**怎么加一版**：改 `versions.json`（id 用「月日-时分」，写标题、一句话、2–5 条改动），然后

```
python3 make_versions.py     # 从 git 取出该 tag 的 app/static/index.html，注入横幅后写 site/versions/<id>/
```

脚本做两件事：把旧页面里写死的 `http://127.0.0.1:8770` 抹成空串（快照由同一个服务提供，同源即可）；注入顶部横幅与一个薄垫片——旧版页面没有 token 概念，垫片给 `fetch` 与 `XMLHttpRequest` 补 `Authorization`，并把探活结果写在横幅上（「数据接口已连接」／「连不上服务」）。所以旧界面能对着当前后端跑，而不是一张死图。

横幅用文档流而不是固定定位：旧页面自带 sticky 页头，固定横幅会压住它 32px。

**这是「界面」的历史，不是「代码」的历史**。后端行为的变化（提示词、清洗规则）在不同版本的界面上看不出差别，要看 git 或下表的说明。`152ecf1` 那一版界面与上一版完全相同，清单里用 `sameAs` 指过去。

## 八、已知限制

- 本机 `models.json` 里目前只有 `deepseek-v4-flash` 可用（其余端点返回 403/404）。该模型是推理模型，生成时程序会显式关闭思考（`thinking: disabled`），否则推理 token 会挤占输出预算、正文为空。换模型可在页面下拉里选。
- 默认不取结构化台账，财务表由模型从评级报告原文整理，数字虽经溯源校验，仍建议抽取两三行与原文核对。
- 业务构成表同样来自评级报告正文的「营业收入构成」表；材料没有分部收入就留空，不硬凑。
- 受限资产、授信、对外担保这类只有评级报告才披露的内容，靠正文引用，不进表。
- 标题行的内部评级代码（如 `【4B】`）属内部结论，程序不猜，导出前在页面上填；不填则显示 `【待填】`。
- 单次生成是「一份材料集出稿」，不做多期版本比较；同一主体要出两版，改材料清单重跑即可。
