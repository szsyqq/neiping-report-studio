# 内评简评报告外部自动生成

把「外部材料（跟踪评级报告／募集说明书／年报）」变成「内部简评报告」的一套可复用资产：**通用模板 + 写作方法论 + 本地工作台**。工作台接财汇 MCP，输入企业名称即可自动取数、下材料、出草稿、导出 Word。

在线入口：<https://szsyqq.github.io/neiping-report-studio/>

## 一、三件产出

| 产出 | 位置 | 用途 |
|---|---|---|
| 通用模板 v1.1 | `01_模板/内评简评报告通用模板_v1.1.md`（人读）/ `.json`（机器读）/ `.docx`（骨架） | 决定报告的骨架、槽位、字数、加粗位置、表格结构，以及**指标行项的选取规则** |
| 写作方法论 v1.1 | `02_方法/内评简评报告写作方法论_v1.1.md` | 决定「材料怎么变成文字」：取数期次规则、六段写法、正面与关注的提炼法、定稿检查表 |
| 工作台 | `app/`（`server.py` + 前端 `static/index.html`） | 检索公告 → 读取或上传材料 → 生成 → 编辑 → 导出 docx |

样例：`03_示例/` 下有两份，一份机场（重资产、准公益性），一份防水材料（制造业、下游地产链），用来对照同一套骨架在不同主体上的落法——两份的章节完全相同，分部板块、资产段重点、财务表行项各不相同，差异全部来自数据而非行业标签。各附 `_draft.json` 中间产物，便于比对。

v1.0 的七个行业指标包已废止（城投／产投／交通运输／制造业／房地产／金融／REITs）。废止原因与替代方案见模板第六节：行业分类靠名称关键词判断，归错一次整张表的行项跟着错；行业清单永远补不全；行业词会渗进判断句变成套话。

## 三、工作台怎么用

页面只有一件事：把四步走完。左侧是主体输入、四步进度与资料清单，右侧是报告纸面，改完就导出。

1. **检索主体**：输入工商全称（简称也能命中）。公告接口不限关键词时按日期倒序返回，所以这里**一次宽查询取回最近 60 条**，在本地按标题分成**跟踪评级报告**与**募集说明书**（各留 12 条）；只有某一类一条都没出现时，才带关键词补查那一次。常态只消耗 1 点财汇额度，最坏 3 点。不走工商、股权、评级历史、存量债券、财务指标、主营构成那六七个接口——单次返回体大、串起来要等十几秒，也把下游提示词撑得很大。
2. **读取材料**：默认勾选各类最新一份。PDF 下载到 `data/`，按页打分生成摘录：跟踪评级报告约 3.2 万字符，募集说明书约 2.6 万字符，一次生成的材料总量控制在 6 万字符上下。**三大报表页先占预算**——合并资产负债表、利润表、现金流量表（含跨页的后半张）优先入选，再按内容价值分配剩余额度；否则财务页会被业务章节挤掉，模型看不到最新一期数字，正文就会写「未披露」。
3. **生成草稿**：约 30–60 秒。台账没有财务数据时，财务表由模型从材料原文的「主要财务数据」表整理（期次取最近三期），程序负责清洗、补千分位、校验自洽；段落与判断由模型写，生成后自动跑五类校验（摘要层数据、数字溯源、期次写法、财务表自洽、「整列未披露但材料里有对应年度报表」）。
4. **校对导出**：页面上逐段可改（摘要、基本情况、总述、各分部、资产、债务、专题），改完导出 docx，文件名带日期，落在 `output/`。

**历史记录**：每次生成自动落一份到 `data/history/`（正文、用的哪几份材料、模型与 token、导出后的 docx 名），页头「历史」打开列表，可一键把某次草稿恢复到编辑区接着改，或直接下当次导出的 Word。列表只读索引文件，点开才读全文，不会因为攒了几十份就变慢；超过 200 条自动淘汰最旧的。

**打包归档**：纸面右上「打包下载」展开一份勾选清单——本次报告（以及此前几版，默认只勾最新一份）、本次读取过的原底稿 PDF（标注页数、大小、来自财汇还是本地上传），外加可选的草稿数据 JSON（正文与表格的结构化数据，方便下次接着改）。勾完得到一个 zip，报告在根目录，底稿归在 `原底稿/` 下。没导出过 Word 也能打包，清单里会出现「按当前内容现场排版」，打包时现生成一份。

**也可以完全不用财汇**：左侧「上传 PDF」支持点选或拖入本机文件，上传后自动解析，直接进第 3 步。上传走裸字节 POST（`/api/upload`），前端用 XHR 显示上传百分比。

**进度不是装饰**：四步都是后台任务（`app/jobs.py`），前端按 `job_id` 轮询真实百分比——检索显示查到哪个关键词，读取材料显示每一份在「下载 12.4MB」还是「解析 74/107 页」，生成显示已用时。没开始的步骤整体灰掉，已完成的打勾。

对应接口：`POST /api/jobs/{search|fetch|generate}` 起任务并拿到 `job_id`，`GET /api/jobs/<id>` 读进度（含逐份材料的明细）；`POST /api/upload?name=文件名` 收 PDF；`/api/export` 仍是同步接口（排版只需秒级）；`GET /api/bundle?company=…&title=…` 列可打包的文件，`POST /api/bundle` 按勾选打 zip（同步返回下载地址）；`GET /api/history` 列历史、`GET /api/history/<id>` 取全文。

**调用统计**：页头右上角一行「累计 N 次 · 财汇 M 点」，点开是明细——今日与累计的生成次数、财汇点数与 token，输入输出拆分、单次平均耗时、缓存命中率，检索／读取／生成／导出四类动作的累计次数，以及**最近调用逐条记录**（时间、动作、主体、这一下花了多少点或多少 token）。不按月切，看的是「这一次点了几下、累计用了多少」。数字全部来自模型返回的 `usage`（端点不回时才按字符估算并标「含估算」）。

财汇点数按调用二级工具的次数记（导航与元数据调用不计），每次检索结束时进度条上直接写「财汇 N 点」，和财汇后台的积分明细能对上。

统计落在 `data/usage.json`（已在 `.gitignore` 里），不是内存计数——服务是后台进程，被系统回收后内存清零，统计随重启归零就没用了。写入用临时文件替换，进程中途被杀也不会留下半个 JSON。`GET /api/stats` 返回同一份汇总。

## 四、分工原则（为什么不容易出错）

- **数字要有出处**：有台账时，业务构成表与财务指标表由程序按台账生成；没有台账（只检索公告或纯上传）时，财务表由模型从材料原文的「主要财务数据」表整理，程序负责补千分位、限三期、查自洽（资产 = 负债 + 权益），并在页面上标注「取自材料原文」。
- **判断归模型**：正文段落、正面／关注的提炼交给模型，但受模板槽位与写作纪律约束（摘要层不写数字、一段一事、不照抄评级机构结论、不按行业套路）。
- **校验兜底**：生成后自动检查五件事——
  - 摘要层是否混入金额／百分比（摘要应为纯定性）；
  - 正文数字能否在台账或材料原文里找到（找不到的会列出来，多为正文自行算的占比与增速，复核算式即可）。材料表格常以万元计、正文按亿元写，比对时两种口径都认；
  - 期次写法是否与台账/材料一致（不允许把「中报」写成 9 月末），且是否把材料里不同期次的数字拼到同一期次；
  - 财务表是否自洽（资产总额 = 负债 + 权益）；
  - 财务表某一期整列写「未披露」、但材料原文里有该年度报表时，单独提示——多半是摘录漏页或漏读，不是材料真的没披露。

## 五、扩展：改规则，不改行业分支

- **加一类指标**：在 `01_模板/…_v1.1.json` 的 `indicator_layers.conditional` 里加一条，写清触发条件（字段可得、某科目占总资产的比例、某损益占利润总额的比例）与优先级。程序按触发条件自动决定这行出不出现，不需要给主体贴行业标签。`base` 是任何主体都有的必选行。
- **改口径**：自算比率在 `app/generator.py` 的 `_calc()`；触发条件解释器在同文件的 `_trigger_ok()`。
- **改版式**：`app/docx_writer.py` 落地模板「格式规范」——楷体_GB2312、五号、行距 1.15、首行缩进 2 字符、段前段后 0、标题与汇总句加粗；块与块之间用空段落分隔（参考件即如此，靠段前段后拉开会挤成一整片）；表格外框上下 1.5pt、内部横竖线 0.5pt、左右不封口，行高 0.4cm 起、单元格垂直居中、禁止跨页断行。
- **分部段不重复导语**：正文里「1）××业务方面，」由程序统一拼，模型只写其后正文。模型若自己写了同样的开头，`generator.clean_segment_body()` 会剥掉，避免出现「2）新材料业务方面，2）新材料业务方面，」。
- **单独复用提示词**：页面上的「复制提示词」把系统提示＋用户提示整段复制出来，可贴到 WorkBuddy 用更强的模型精修同一份材料。

## 六、部署到 GitHub Pages

`site/` 是 Pages 根目录：`index.html` 是工作台前端，`docs/` 放模板与方法论的 HTML/JSON/DOCX。

```bash
cd /Users/panyp/WorkBuddy/评级报告外部自动生成
python3 app/md2html.py                # 模板与方法论 md → 可直接阅读的 html
cp app/static/index.html site/index.html
git add -A && git commit -m "update" && git push
```

**为什么 Pages 上的页面必须连本机后端**：财汇 MCP 不返回 `Access-Control-Allow-Origin`，浏览器直连会被 CORS 拦死。因此在线页面定位是「入口」——打开后它去 ping `http://127.0.0.1:8770`，连通就正常用（跨域头已由 `server.py` 放开，服务只监听本机回环）；不通就显示启动命令，并允许在页面上改服务地址（存 `localStorage.apiBase`）。

## 七、已知限制

- 本机 `models.json` 里目前只有 `deepseek-v4-flash` 可用（其余端点返回 403/404）。该模型是推理模型，生成时程序会显式关闭思考（`thinking: disabled`），否则推理 token 会挤占输出预算、正文为空。换模型可在页面下拉里选。
- 默认不取结构化台账，财务表由模型从评级报告原文整理，数字虽经溯源校验，仍建议抽取两三行与原文核对。
- 业务构成表同样来自评级报告正文的「营业收入构成」表；材料没有分部收入就留空，不硬凑。
- 受限资产、授信、对外担保这类只有评级报告才披露的内容，靠正文引用，不进表。
- 标题行的内部评级代码（如 `【4B】`）属内部结论，程序不猜，导出前在页面上填；不填则显示 `【待填】`。
- 单次生成是「一份材料集出稿」，不做多期版本比较；同一主体要出两版，改材料清单重跑即可。
